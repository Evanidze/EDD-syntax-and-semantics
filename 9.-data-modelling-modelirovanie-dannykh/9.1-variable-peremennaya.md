# 9.1 VARIABLE (переменная)

## 9.1.1 General structure

**VARIABLE** описывает параметры, содержащиеся в устройстве или в приложении EDD. Эти элементы данных включают:

* Процессные данные (process data)
* Статусные данные (status)
* Параметры конфигурации (configuration properties)

Конструкция **VARIABLE** предоставляет широкий набор описательных свойств, позволяющих полностью характеризовать любой элемент данных.

Избегайте ситуаций, когда методы в одном списке ACTION изменяют этот список, так как перечень методов для любого ACTION может быть условным. Непредвиденные результаты могут возникнуть, если условная логика изменит список ACTION во время его обработки.

{% code title="Lexical structure" %}
```c
VARIABLE identifier { 
    LABEL string-value; 
    HELP string-value; 
    CLASS variable-class-specifier [&variable-class-specifier]*;
    CONSTANT_UNIT string-value; 
    DEFAULT_VALUE default-value-specifier; 
    HANDLING handling-specifier; 
    HEIGHT height-width-specifier; 
    INITIAL_VALUE initial-value-specifier; 
    POST_EDIT_ACTIONS { actions-specifier }
    POST_READ_ACTIONS { actions-specifier } 
    POST_ROSTUPDATE_ACTIONS { actions-specifier } 
    POST_USERCHANGE_ACTIONS { actions-specifier } 
    POST_WRITE_ACTIONS { actions-specifier } 
    PRE_EDIT_ACTIONS { actions-specifier } 
    PRE_READ ACTIONS { actions-specifier } 
    PRE_WRITE_ACTIONS { actions-specifier } 
    PRIVATE boolean-specifier; 
    REFRESH_ACTIONS { actions-specifier } 
    RESPONSE_CODES response-codes-specifier; // не поддерживается в HART
    TYPE variable-type; 
    VALIDITY boolean-specifier; 
    VISIBILITY boolean-specifier; 
    WIDTH height-width-specifier; 
    WRITE_MODE write-mode-specifier; // не поддерживается в HART
}
```
{% endcode %}

## 9.1.2 CLASS (КЛАСС)

Атрибут CLASS определяет, как VARIABLE используется устройством и приложением EDD для целей организации и отображения. Классы используются для моделирования применения элемента EDD (например, они указывают, что элемент используется для диагностики состояния устройства). Кроме того, элемент EDD может быть предоставлен для помощи приложению EDD в доступе к устройству. В этом случае элемент EDD имеет класс LOCAL и фактически не существует в устройстве. CLASS не должен содержать условных выражений.

Определение CLASS основано на модели, в которой устройство состоит из нескольких различных функциональных блоков. Каждый блок имеет вход и производит выход. Блоки могут комбинироваться различными способами для создания различных функциональных возможностей.

{% code title="Lexical structure" overflow="wrap" %}
```c
CLASS variable-class-specifier [&variable-class-specifier]* ;
variable-class-specifier := ALARM | ANALOG_INPUT | ANALOG_OUTPUT | COMPUTATION | CONSTANT | CONTAINED | CORRECTION | DEVICE | DIAGNOSTIC | DIGITAL_INPUT | DIGITAL_OUTPUT | DISCRETE | DISCRETE_INPUT | DISCRETE_OUTPUT | DYNAMIC | FREQUENCY | FREQUENCY_INPUT | FREQUENCY_OUTPUT | HART | INPUT | IS_CONFIG | LOCAL | LOCAL_A | LOCAL_B | LOCAL_DISPLAY | MODE | OPERATE | OPTIONAL | OUTPUT | SERVICE | SPECIALIST | TEMPORARY | TUNE
```
{% endcode %}

## 9.1.3 CONSTANT\_UNIT (постоянная единица измерения)

Атрибут **CONSTANT\_UNIT** применяется, если VARIABLE имеет неизменяемый код единиц измерения (например, демпфирование всегда указывается в секундах). CONSTANT\_UNIT задаётся в виде строки, которая отображается вместе со значением VARIABLE.

Для VARIABLE без CONSTANT\_UNIT возможны два варианта:

* Единицы измерения не связаны с переменной
* Единицы измерения не являются постоянными

Если инженерные единицы могут изменяться, они должны быть представлены с помощью отношения **UNIT**.

{% code title="Lexical structure" %}
```c
CONSTANT_UNIT string-value | string-value<cond>;
```
{% endcode %}

## 9.1.4 DEFAULT\_VALUE

Атрибут **DEFAULT\_VALUE** определяет значение по умолчанию для VARIABLE. Он позволяет EDD указать логически согласованное и разумное значение, которое приложение EDD может использовать, когда устройство не находится в физическом контакте с приложением EDD (например, при создании новой конфигурации устройства в автономном режиме). Если INITIAL\_VALUE не определен, DEFAULT\_VALUE используется в качестве INITIAL\_VALUE.

Тип выражения должен соответствовать типу VARIABLE. Выражение должно вычисляться в константу без необходимости связи с реальным устройством. DEFAULT\_VALUE также может быть задан через атрибут TYPE VARIABLE.

Для арифметических типов DEFAULT\_VALUE указывается без масштабирования.

**Профиль связи: HART**

Когда **DEFAULT\_VALUE** не указан, VARIABLE принимает значение из колонки "Начальное значение" Таблицы B.2 до тех пор, пока:

* Пользователь не изменит его
* Связь с устройством не изменит значение VARIABLE

Если начальное значение из Таблицы B.2 выходит за пределы диапазона **MIN\_VALUE**/**MAX\_VALUE**, оно автоматически устанавливается на ближайшее допустимое значение.

{% code title="Lexical structure" %}
```c
// communication profiles: FF, ISA100, HART
DEFAULT_VALUE expression;
// communication profiles: CS, GPE, PB, PN
DEFAULT_VALUE expressiion<cond>;
```
{% endcode %}

Тип выражения должен соответствовать типу VARIABLE.

## 9.1.5 INITIAL\_VALUE

Атрибут **INITIAL\_VALUE** определяет значение VARIABLE, отображаемое при первом запуске устройства.

**Основные характеристики:**

* **DEFAULT\_VALUE** часто является условным и зависит от других параметров
* **INITIAL\_VALUE** используется для восстановления настроек по умолчанию
* Доступен для всех типов данных и **не может быть условным**

**Справочные данные:**\
Колонка _"Initial value"_ в Таблице B.2 содержит начальные значения в зависимости от типа VARIABLE.

{% code title="Lexical structure" %}
```c
INITIAL_VALUE expression;
```
{% endcode %}

Тип выражения должен соответствовать типу VARIABLE.

## 9.1.6 POST\_EDIT\_ACTIONS

Атрибут **POST\_EDIT\_ACTIONS** определяет **METHODS**, выполняемые после завершения редактирования VARIABLE пользователем.

**Ключевые правила:**

1. **Порядок выполнения**: METHODS выполняются в порядке их объявления
2. **Отмена редактирования**: POST\_EDIT\_ACTIONS не активируются при отмене изменений пользователем
3. **Обработка ошибок**:
   * При аварийном завершении METHOD последующие METHODS не выполняются
   * При аварийном завершении кэш данных уже обновлен новым значением и не откатывается

**Рекомендации по применению**:

* Используется для:
  * Отображения информации/предупреждений
  * Манипуляции с другими переменными
* Вызывается после изменения значения переменной

**Обработка ошибок**:\
При аварийном завершении METHOD приложение EDD должно уведомить пользователя о нарушении процесса.

{% code title="Lexical structure" overflow="wrap" %}
```c
POST_EDIT_ACTIONS {action-specifier [, actions-specifiet]*] }
actions-specifier := [reference<cond> [, reference<cond>]*] | [DEFINITION {compound-statement }]<cond>
```
{% endcode %}

## 9.1.7 POST\_READ\_ACTIONS

Атрибут **POST\_READ\_ACTIONS** определяет **METHODS**, которые должны выполняться после чтения VARIABLE из устройства, то есть после получения ответа на чтение и должны работать с полученными данными. POST\_READ\_ACTIONS выполняются сразу после получения ответов и до отправки любых дополнительных запросов на связь. Указанные METHODS должны выполняться в порядке их объявления. Если METHOD завершается по незапланированной причине, следующие METHODS не выполняются.

Если один из METHODS **PRE\_READ\_ACTIONS** аварийно завершается, VARIABLE не должна читаться из устройства, и METHODS **POST\_READ\_ACTIONS** не должны вызываться. Если один из METHODS **POST\_READ\_ACTIONS** аварийно завершается, приложение EDD должно указать, что во время процесса чтения произошла ошибка. Это указание может быть таким же, как пометка переменной как недействительной или непрочитанной, или может быть отдельным указанием. Если метод использует встроенную функцию связи для чтения переменной, и **POST\_READ\_ACTION** для этой переменной аварийно завершается, это не влияет на статус возврата встроенной функции связи. Разработчики DD должны включать логику непосредственно в код METHOD для обработки/предотвращения условий, которые могут привести к аварийному завершению **POST\_READ\_ACTION**.

{% code title="Lexical structure" overflow="wrap" %}
```c
POST_READ_ACTIONS {action-specifier [, actions-specifiet]*] }
actions-specifier := [reference<cond> [, reference<cond>]*] | [DEFINITION {compound-statement }]<cond>
```
{% endcode %}

Описание атрибутов представлено в таблице 18.

## 9.1.8 POST\_RQSTUPDATE\_ACTIONS

**POST\_RQSTUPDATE\_ACTIONS** поддерживаются только симуляторами устройств. В других приложениях EDD (кроме симуляторов) этот атрибут игнорируется.

Атрибут **POST\_RQSTUPDATE\_ACTIONS** определяет **METHODS**, которые выполняются при:

1. Записи значения VARIABLE через коммуникационный интерфейс EDD-приложения
2. Обновлении VARIABLE через пакет запроса (включая случаи, когда значение не изменилось)

**Ключевые особенности выполнения:**

* Действия выполняются ДО обновления последующих переменных в принимаемом пакете
* Все METHODS должны завершиться ДО генерации симулятором ответного пакета
* METHODS выполняются строго последовательно
* Аварийное завершение METHOD прекращает выполнение последующих METHODS

{% code title="Lexical structure" %}
```c
POST_RQSTUPDATE_ACTIONS {
    reference<cond> [, reference<cond>]*
}
```
{% endcode %}

### 9.1.15.2 MIN\_VALUE, MAX\_VALUE

**MIN\_VALUE** и **MAX\_VALUE** определяют нижнюю и верхнюю границы значений, которые могут быть установлены для VARIABLE. Если переменная является динамической (см. атрибут CLASS), устройство может устанавливать значение переменной вне диапазона, заданного атрибутами MIN\_VALUE и MAX\_VALUE. Минимальное и максимальное значения сравниваются с не масштабированным значением. Поддержка атрибутов MIN\_VALUE и MAX\_VALUE зависит от атрибута TYPE. В подразделах, посвященных каждому типу переменных, указаны лексическая структура и поддержка для каждого TYPE.

VARIABLE может иметь несколько минимальных или максимальных значений, например, для указания нескольких допустимых диапазонов (например, переменная может иметь диапазон чуть выше нуля и чуть ниже нуля, но не равный нулю). Когда имеется несколько минимальных или максимальных значений, используются дополнительные целые числа для нумерации каждого MIN\_VALUE или MAX\_VALUE.

Диапазон, заданный парой MIN\_VALUE и MAX\_VALUE, не должен пересекаться с другим заданным диапазоном. Если MIN\_VALUE/MAX\_VALUE не имеет соответствующего MAX\_VALUE/MIN\_VALUE, верхняя/нижняя граница считается неограниченной и не требует указания. MIN\_VALUE/MAX\_VALUE также может быть задано выражением (см. раздел 18).

Значения, полученные от устройства, должны приниматься и отображаться, даже если они выходят за пределы **MIN\_VALUE** и **MAX\_VALUE**.

{% code title="Lexical structure" %}
```c
[MAX_VALUE | MIN_VALUE] [n]? expression<cond>;
```
{% endcode %}

Тип выражения должен соответствовать типу VARIABLE.

#### 9.1.15.4.3 EDIT\_FORMAT

Определяет способ редактирования значения VARIABLE. Строка **EDIT\_FORMAT** должна соответствовать функции **scanf** языка программирования C (см. ISO/IEC 9899:1999), без начального символа '%'. Формат редактирования управляет только обработкой вводимых пользователем значений. Если атрибут EDIT\_FORMAT не указан, используется DISPLAY\_FORMAT переменной.

{% code title="Lexical structure" %}
```c
EDIT_FORMAT string-value<cond>;
```
{% endcode %}

Формат редактирования состоит из необязательного числового спецификатора ширины, необязательной десятичной точки со спецификатором точности и спецификатора типа. Синтаксис следует шаблону: флаги\* ширина\* \[.точность]\* тип. Флаги могут включать несколько спецификаторов, таких как решётка (#) и ноль (0), которые используются так же, как и в функции printf стандарта ANSI C.

Спецификатор ширины представляет собой целое число в десятичном формате, которое определяет максимальное количество символов для ввода или обработки. Если ширина не указана, по умолчанию будет использовано значение, позволяющее вводить наибольшее положительное и наименьшее отрицательное значение, которое может содержать переменная. Этот спецификатор полностью соответствует спецификатору ширины, используемому в функции scanf стандарта ANSI C.

Необязательный спецификатор точности - это целое число в десятичном формате, определяющее максимальное количество значащих цифр справа от десятичной точки. Этот спецификатор игнорируется, когда спецификатор типа принадлежит набору целочисленных входных данных 'diouxX', и должен быть меньше спецификатора ширины (если он присутствует). Если спецификатор точности отсутствует в строке формата редактирования, на цифры справа от десятичной точки не накладывается ограничений на ввод (за исключением ограничения по ширине, если оно есть).

Спецификатор типа представляет собой один из типов ввода 'diouxXeEffgG', как указано для функции scanf.

#### 9.1.15.4.4 SCALING\_FACTOR

Атрибут **SCALING\_FACTOR** указывает, что отображаемое значение VARIABLE не соответствует значению, возвращаемому устройством. Отображаемое значение вычисляется путем умножения значения, полученного от устройства, на заданный коэффициент. Таким образом, процессор EDDL должен умножать значение VARIABLE, полученное от устройства, на SCALING\_FACTOR перед отображением. Значение SCALING\_FACTOR не должно быть равно нулю.

SCALING\_FACTOR может быть задан выражением (см. раздел 18). Масштабирующий коэффициент применяется исключительно для целей отображения. Во всех остальных случаях (например, при доступе к VARIABLE из метода или сравнении с минимальным/максимальным значением) значение остается эквивалентным и в той же форме, что и не масштабированное значение, возвращаемое устройством. Минимальные и максимальные значения при использовании с масштабирующим коэффициентом также указываются в не масштабированной форме.

SCALING\_FACTOR не влияет на DISPLAY\_FORMAT VARIABLE.

{% code title="Lexical structure" %}
```c
SCALING_FACTOR [double-value<cond> | double-expression<cond>];
```
{% endcode %}

Размер типа данных в октетах. Размер задается целочисленной константой от 1 до 8 включительно. Этот параметр является необязательным. Значение по умолчанию - 1.

### 9.1.15.5 DATE, DATE\_AND\_TIME, DURATION, TIME, TIME\_VALUE

#### 9.1.15.5.1 General structure

Переменные (**VARIABLES**) типов **DATE**, **DATE\_AND\_TIME**, **DURATION**, **TIME**, **TIME\_VALUE** используются для работы с датами, временем и временными интервалами:

* **DATE** — содержит календарную дату;
* **DATE\_AND\_TIME** — объединяет календарную дату и время;
* **DURATION** — временной интервал в миллисекундах (мс) с учётом количества дней;
* **TIME** — время с указанием даты;
* **TIME\_VALUE** — представляет:
  * Разницы во времени
  * Время суток
  * Абсолютные временные значения\
    _&#x421; требуемой точностью для синхронизации часов приложений._

Тип **DATE** указывает, что VARIABLE представляет собой беззнаковое целое число размером три октета, кодирующее День, Месяц и Год. Формат кодировки октетов указан в разделе **B.2.2**.

{% code title="Lexical structure - DATE" %}
```c
DATE [{
    DEFAULT_VALUE unsigned-integer-value ;
    INITIAL_VALUE unsigned-integer-constant ;
    [MAX_VALUE[n] ? unsigned-integer-value ;]* 
    [MIN_VALUE[n] ? unsigned-integer-value ;]* 
}]
```
{% endcode %}

Для **DEFAULT\_VALUE** константное выражение должно представлять собой беззнаковое 3-байтовое целое число, где:

* **Старший байт (MSByte)**: День
* **Младший байт (LSByte)**: (Год - 1900)

**Пример**:\
Дата 24 июня 1993 года кодируется как:\
`Day = 24` (старший байт)\
`Month = 6` (средний байт)\
`Year = 1993 - 1900 = 93` (младший байт)

```c
DEFAULT_VALUE (((24<<8)+6)<<8)+93;
```

Тип **DATE\_AND\_TIME** указывает, что VARIABLE представляет собой:

* Беззнаковое целое число
* Размером **7 октетов**
* Кодирующее календарную дату _и_ время

**Формат кодировки** октетов описан в разделе **B.2.3**.

{% code title="Lexical structure - DATE_AND_TIME" %}
```c
DATE_AND_TIME [{
    DEFAULT_VALUE unsigned-integer-value ;
    INITIAL_VALUE unsigned-integer-constant ;
    [MAX_VALUE[n] ? unsigned-integer-value ;]* 
    [MIN_VALUE[n] ? unsigned-integer-value ;]* 
    TIME_FORMAT string-value;
}]?
```
{% endcode %}

Тип **DURATION** определяет, что VARIABLE представляет собой беззнаковое целое число размером **6 октетов**, где:

1. **Структура данных**:
   * Первые 4 бита всегда равны нулю
   * Биты 0-27: время в миллисекундах (мс) с полуночи
   * Биты 28-43: количество дней (16-битное двоичное значение)
2. **Кодировка**:\
   Подробное описание формата приведено в разделе **B.2.4**.

{% code title="Lexical structure - DURATION" %}
```c
DURATION [{
    DEFAULT_VALUE unsigned-integer-value ;
    INITIAL_VALUE unsigned-integer-constant ;
    [MAX_VALUE[n] ? unsigned-integer-value ;]* 
    [MIN_VALUE[n] ? unsigned-integer-value ;]* 
    TIME_FORMAT string-value;
}]?
```
{% endcode %}

Тип **TIME** определяет, что VARIABLE представляет собой беззнаковое целое число размером **6 октетов** со следующей структурой:

1. **Временная часть**:
   * Время в миллисекундах (мс), отсчитываемое от полуночи
   * Значение "0" соответствует моменту полуночи
2. **Дата**:
   * Количество дней, прошедших с **01.01.1984**
   * Дата 01.01.1984 соответствует значению "0"

**Формат кодирования** октетов приведен в разделе **B.2.5**.

{% code title="Lexical structure - TIME" %}
```c
TIME [{
    DEFAULT_VALUE unsigned-integer-value ;
    INITIAL_VALUE unsigned-integer-constant ;
    [MAX_VALUE[n] ? unsigned-integer-value ;]* 
    [MIN_VALUE[n] ? unsigned-integer-value ;]* 
    TIME_FORMAT string-value;
}]?
```
{% endcode %}

Тип **TIME\_VALUE** определяет, что VARIABLE представляет собой:

* Беззнаковое целое число
* Размером **4 или 8 октетов**
* Фиксированную точку времени с шагом **1/32 мс**

**Формат кодирования** октетов приведен в разделе **B.2.6**.

{% code title="Lexical structure - TIME_VALUE" %}
```c
TIME_VALUE (size) [{
    DEFAULT_VALUE unsigned-integer-value ;
    INITIAL_VALUE unsigned-integer-constant ;
    DISPLAY_FORMAT string-value;
    EDIT_FORMAT string-value;
    [MAX_VALUE[n] ? unsigned-integer-value ;]* 
    [MIN_VALUE[n] ? unsigned-integer-value ;]* 
    TIME_FORMAT string-value;
    TIME_SCALE time-scale-specifier;
}]?
```
{% endcode %}

Для **DEFAULT\_VALUE** константное выражение должно представлять собой беззнаковое 4- или 8-байтовое целое число. Например, кодировка 4-байтового значения TIME\_VALUE для времени 05:14:26 может быть выражена как:

```
DEFAULT_VALUE ((5*60+14)*60+26)*32000;
```

**Требования к MIN\_VALUE и MAX\_VALUE**:

* Должны быть представлены как:
  * Беззнаковое 4- или 8-байтовое целое число (аналогично DEFAULT\_VALUE)
  * Ссылка на другую VARIABLE типа TIME\_VALUE

Атрибуты типов **DATE**, **DATE\_AND\_TIME**, **DURATION**, **TIME**, **TIME\_VALUE** определены в **Таблице 25**.

{% hint style="danger" %}
**Примечание**: атрибуты DEFAULT\_VALUE, INITIAL\_VALUE, size недоступны в HART
{% endhint %}

#### 9.1.15.5.2 TIME\_FORMAT

Атрибут **TIME\_FORMAT** определяет формат отображения и редактирования VARIABLE. Строки TIME\_FORMAT могут включать спецификаторы формата функции **strftime** языка C:

* Базовые: `%H`, `%M`, `%S`, `%T`
* Для **DATE\_AND\_TIME**, **TIME** и **TIME\_VALUE(8)** дополнительно применяются:\
  `%a %A %b %B %c %d %D %e %F %g %G %h %m %x %y %Y`

**Ограничения для DURATION**:

* Спецификаторы `%I` и `%p` не поддерживаются
* При значениях >24 часов возможны некорректные результаты
* Возможна потеря точности ниже миллисекунд

{% hint style="danger" %}
**Важно**: Если указан TIME\_FORMAT, атрибуты DISPLAY\_FORMAT и EDIT\_FORMAT **не должны** использоваться.
{% endhint %}

{% code title="Lexical structure" %}
```c
TIME_FORMAT string-value<cond>
```
{% endcode %}

#### 9.1.15.5.3 TIME\_SCALE

Атрибут **TIME\_SCALE** определяет масштабирование VARIABLE с возможными значениями:

* **SECONDS** (секунды)
* **MINUTES** (минуты)
* **HOURS** (часы)

**Применение масштабирования:**

1. Автоматически устанавливает коэффициент преобразования:
   * SECONDS → 1/32 000
   * MINUTES → 1/1 920 000
   * HOURS → 1/115 200 000
2. Задает постоянные единицы измерения:
   * "s" (секунды)
   * "min" (минуты)
   * "h" (часы)

**Правила использования:**

* При указании TIME\_SCALE можно дополнительно задавать DISPLAY\_FORMAT и EDIT\_FORMAT
* Без TIME\_SCALE допустим только атрибут TIME\_FORMAT

**Особое требование для TIME\_VALUE(8):**\
Если TIME\_SCALE отсутствует, приложение EDD должно отображать и дату, и время.

Для переменных **TYPE TIME\_VALUE(4)** при отсутствии **TIME\_SCALE**:

* По умолчанию применяется **TIME\_FORMAT = "%T"**
* В противном случае используется формат по умолчанию, как для переменных **TYPE FLOAT**

**TIME\_SCALE** является масштабирующим коэффициентом, и для него действуют те же правила, что и для **SCALING\_FACTOR**.

{% code title="Lexical structure" %}
```c
TIME_SCALE [SECONDS, MINUTES, HOURS]<cond>
```
{% endcode %}

#### 9.1.15.5.4 size

Размер типа данных в октетах. Допустимые значения: **4** или **8**.

* Для **Foundation Fieldbus (FF)**: значение по умолчанию = **8**
* Для всех остальных протоколов: значение по умолчанию = **4**

_Примечание:_ Данный атрибут применяется только для типа **TIME\_VALUE**.

### 9.1.15.6 BIT\_ENUMERATED

#### 9.1.15.6.1 General structure

Переменная типа **BIT\_ENUMERATED** представляет собой беззнаковое целое число, интерпретируемое как набор битовых флагов. Каждый бит идентифицируется значением своей позиции:

* Бит 0: значение 1 (2⁰)
* Бит 1: значение 2 (2¹)
* Бит 2: значение 4 (2²)
* Бит 3: значение 8 (2³)
* И так далее

**Особенности работы:**

1. Доступ к отдельным битам осуществляется через:
   * Имя переменной
   * Бит-маску (как указано в разделе **16.3**)
2. Требования к бит-маске:
   * Должна быть целочисленной константой
   * Должна указывать на один конкретный бит

{% code title="Lexical structure" %}
```c
BIT_ENUMERATED (size) {
    DEFAULT_VALUE unsigned-integer-value ;
    INITIAL_VALUE unsigned-integer-constant ;
    [[{ value , description , help , class , status-class , action }, ]<cond>]*
    [{ value , description , help , class , status-class , action }]<cond>
}
```
{% endcode %}

{% hint style="danger" %}
Примечание: атрибуты DEFAULT\_VALUE, INITIAL\_VALUE недоступны в HART
{% endhint %}
