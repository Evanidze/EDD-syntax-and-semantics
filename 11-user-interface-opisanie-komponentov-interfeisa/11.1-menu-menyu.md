# 11.1 MENU (Меню)

## 11.1.1 General structure

**MENU** организует переменные, методы и другие элементы, указанные в EDDL, в иерархическую структуру. **MENU** является основным механизмом для организации информации об устройстве и поддержки взаимодействия пользователя с устройством. Пользовательское приложение может использовать **MENU\_ITEMS** для отображения и ввода информации в упорядоченном и последовательном виде. Иерархии **MENU** создаются путем определения меню и последующего включения его в качестве элемента другого **MENU**.

**Правила каскадирования для MENU (родитель) и MENU\_ITEMS (потомки):**

* **INIT\_ACTIONS**, **PRE\_EDIT\_ACTIONS**, **PRE\_READ\_ACTIONS** и **PRE\_WRITE\_ACTIONS** запускаются и завершаются сначала для **MENU** (родитель), а затем для **MENU\_ITEMS** (потомки), если иное не указано в другом разделе.
* **EXIT\_ACTIONS**, **POST\_EDIT\_ACTIONS**, **POST\_READ\_ACTIONS** и **POST\_WRITE\_ACTIONS** запускаются и завершаются сначала для **MENU\_ITEMS** (потомки), а затем для **MENU** (родитель).
* Элементы одного уровня (ITEMS в пределах одного **MENU**) не должны зависеть друг от друга при отображении (т.е. не следует предполагать, что порядок элементов определяет момент запуска действий).

**Дополнительные правила:**

* Все действия, если не указано иное, должны запускаться как для **ONLINE**, так и для **OFFLINE** доступа.
* Если для **VARIABLE** требуется специальная обработка при доступе, она должна выполняться в действиях **VARIABLEs**, а не в действиях **MENU**.

**Если список действий (ACTIONS) для MENU является условным**, могут возникнуть непредвиденные результаты, если условная логика изменит список **ACTIONS** во время их выполнения.

**Приложение D.1** содержит примеры последовательностей выполнения **ACTIONS** для **MENUs**.

{% code title="Lexical structure" %}
```c
MENU identifier {
    LABEL string-value;
    HELP string-value;
    ACCESS [OFFLINE | ONLINE]; // недоступно в HART
    EXIT_ACTIONS { actions-specifier };
    INIT_ACTIONS { actions-specifier };
    ITEMS { menu-item-specifier [, menu-item-specifier]* };
    POST_EDIT_ACTIONS { actions-specifier }; // недоступно в HART
    POST_READ_ACTIONS { actions-specifier };
    POST_WRITE_ACTIONS { actions-specifier };
    PRE_EDIT_ACTIONS { actions-specifier };
    PRE_READ_ACTIONS { actions-specifier };
    PRE_WRITE_ACTIONS { actions-specifier };
    STYLE [DIALOG | WINDOW | PAGE | GROUP | MENU | TABLE];
    VALIDITY boolean-specifier;
    VISIBILITY boolean-specifier;
}
```
{% endcode %}

## 11.1.2 ACCESS (Доступ)

**Атрибут ACCESS** определяет, откуда берутся элементы, отображаемые или используемые в **MENU**:

* С устройства (**ONLINE**)
* Локально (**OFFLINE**)

Если атрибут **ACCESS** не определен, применяется значение **ACCESS** родительского **MENU**.

{% code title="Lexical structure" %}
```c
ACCESS [OFFLINE | ONLINE];
```
{% endcode %}

Подробное описание атрибутов приведено ниже.

<table><thead><tr><th width="106">Значение атрибута</th><th>Описание</th></tr></thead><tbody><tr><td>OFFLINE</td><td>Значения элементов, отображаемых в MENU, считываются локально.</td></tr><tr><td>ONLINE</td><td>Значения элементов, отображаемых в MENU, должны считываться с устройства и обновляться через соответствующие интервалы времени.</td></tr></tbody></table>

{% hint style="info" %}
**Примечание:** Реализация определяет момент передачи измененных значений на устройство (обычно после единичного ввода или завершения работы с MENU для атрибута ONLINE ACCESS, либо через отдельное меню для обновления устройства).
{% endhint %}

## 11.1.3 EXIT\_ACTIONS

**Атрибут EXIT\_ACTIONS** определяет **METHODs**, которые должны выполняться после завершения работы приложения EDD с **MENU**, даже если **INIT\_ACTIONS** меню были прерваны.

**Правила выполнения:**

* Указанные **METHODs** выполняются в порядке их объявления
* При незапланированном завершении **METHOD** последующие методы не выполняются
* Приложение EDD игнорирует любые ошибки, приводящие к прерыванию **EXIT\_ACTIONS**

**См. примеры в разделе D.1.3.**

{% code title="Lexical structure" %}
```c
EXIT_ACTIONS { actions-specifier }
actions-specifier := [reference<cond> [, reference<cond>]*]?
(DEFINITION { compound-statement }]<cond>?
```
{% endcode %}

**Атрибуты EXIT\_ACTIONS** определены в **Таблице 82**.

## 11.1.4 INIT\_ACTIONS

**Атрибут INIT\_ACTIONS** определяет **METHODS**, выполняемые перед получением **ITEMS** из **MENU**.

**Ключевые характеристики:**

* **INIT\_ACTIONS** запускаются однократно и не повторяются, пока **MENU** не будет закрыт и открыт заново
* При закрытии **MENU** со стилем **WINDOW** или **DIALOG** все содержащиеся элементы также закрываются

**Правила выполнения:**

1. **METHODS** выполняются последовательно в порядке объявления
2. При аварийном завершении **METHOD**:
   * Последующие **METHODS** не выполняются
   * Пользователь получает уведомление об ошибке
   * Содержимое **MENU** не отображается (но сам **MENU** рендерится как пустой, например, **GROUP** или **PAGE** показывают только свой **LABEL**)

**Приоритет выполнения:**\
**INIT\_ACTIONS** меню должны завершиться до запуска любых других **ACTIONS** в этом **MENU**.

**Примеры:** См. раздел **D.1.2**.

{% code title="Lexical structure" %}
```c
INIT_ACTIONS { actions-specifier }
actions-specifier := [reference<cond> [, reference<cond>]*]?
(DEFINITION { compound-statement }]<cond>?
```
{% endcode %}

**Атрибуты INIT\_ACTIONS** определены в **Таблице 82**.

## 11.1.5 ITEMS (Элементы)

**Атрибут ITEMS** определяет выбранные элементы EDD, которые должны отображаться пользователю, а также дополнительные параметры для управления обработкой каждого элемента.

{% hint style="info" %}
**Примечание 1:** Элементы MENU отображаются пользователю в порядке их перечисления.
{% endhint %}

{% hint style="info" %}
**Примечание 2:**

* Для вертикальных меню первый элемент отображается сверху, последний - снизу.
* Для горизонтальных меню первый элемент отображается слева, последний - справа.
{% endhint %}

{% code overflow="wrap" %}
```c
ITEMS {
    menu-item-specifier [, menu-item-specifier]*
}
menu-item-specifier := 
    [menu-reference [(REVIEW)]?]<cond> 
    | [variable-reference [([DISPLAY_VALUE | HIDDEN | READ_ONLY | NO_LABEL | NO_UNIT])]?]<cond>
    | [image-reference [([INLINE | NO_LABEL | ALIGN_LEFT | ALIGN_RIGHT])]?]<cond> 
    | reference<cond> 
    | string-constant<cond> 
    | SEPARATOR<cond> 
    | ROWBREAK 
    | COLUMNBREAK
```
{% endcode %}

**Элементы MENU** определены в **Таблице 80**.

## 11.1.6 POST\_EDIT\_ACTIONS

**Атрибут POST\_EDIT\_ACTIONS** определяет **METHODS**, которые должны выполняться перед сохранением значений переменных в онлайн или оффлайн набор данных.

**Условия выполнения:**

* Если **MENU** находится в прерванном состоянии (сбой **INIT\_ACTIONS** или **PRE\_READ\_ACTIONS**), **POST\_EDIT\_ACTIONS** не активируются
* Указанные **METHODS** выполняются последовательно в порядке их объявления
* При аварийном завершении **METHOD** последующие методы не выполняются

**Обработка ошибок:**\
Если операция **POST\_EDIT\_ACTION** завершается неудачно:

1. Приложение EDD уведомляет пользователя о невозможности завершить сохранение
2. **POST\_EDIT\_ACTIONS** родительских **MENU** не запускаются
3. Операция сохранения прерывается
4. Пользователь может повторить попытку сохранения

**Примеры:** См. раздел **D.1.9**.

{% code title="Lexical structure" overflow="wrap" %}
```c
POST_EDIT_ACTIONS {actions-specifier}
action-specifier := [reference<cond> [, reference<cond>]*]? [DEFINITION {compound-statement}]<cond>?
```
{% endcode %}

## 11.1.7 POST\_READ\_ACTIONS

**POST\_READ\_ACTIONS** активируются только при **ONLINE**-доступе. Это включает случаи, когда атрибут **ACCESS** меню имеет значение **ONLINE**, даже если сессия в целом работает в **OFFLINE**-режиме.

Атрибут **POST\_READ\_ACTIONS** определяет **METHODS**, которые должны выполняться после чтения всех **VARIABLES** в указанном **MENU**. Если **MENU** не содержит **VARIABLES**, **POST\_READ\_ACTIONS** запускаются сразу после обработки всех элементов, указанных в атрибуте **ITEMS**.

Если **MENU** находится в прерванном состоянии (сбой **INIT\_ACTIONS** или **PRE\_READ\_ACTIONS**), **POST\_READ\_ACTIONS** не активируются. Указанные **METHODS** выполняются в порядке их объявления. Если выполнение **METHOD** завершается по незапланированной причине:

* Последующие **METHODS** не выполняются
* Приложение EDD игнорирует ошибку

**POST\_READ\_ACTIONS** выполняются только один раз после первого запуска и не активируются повторно, пока меню не будет закрыто и открыто заново. При закрытии **MENU** со стилем **WINDOW** или **DIALOG** все вложенные элементы также закрываются.

Примеры см. в разделах **D.1.5** и **D.1.6**.

{% code title="Lexical structure" overflow="wrap" %}
```c
POST_READ_ACTIONS {actions-specifier}
action-specifier := [reference<cond> [, reference<cond>]*]? [DEFINITION {compound-statement}]<cond>?
```
{% endcode %}

**Атрибуты POST\_READ\_ACTIONS** определены в **Таблице 82**.

## 11.1.8 POST\_WRITE\_ACTIONS

**POST\_WRITE\_ACTIONS** активируются только при **ONLINE**-доступе. Это включает случаи, когда атрибут **ACCESS** меню имеет значение **ONLINE**, даже если сессия в целом работает в **OFFLINE**-режиме. Атрибут **POST\_WRITE\_ACTIONS** определяет **METHODs**, которые должны выполняться после записи всех **VARIABLES** на устройство. Это включает **VARIABLES** из разных **MENUs**, которые могли быть изменены во время сеанса редактирования.

Если **MENU** находится в прерванном состоянии (сбой **INIT\_ACTIONS** или **PRE\_READ\_ACTIONS**), **POST\_WRITE\_ACTIONS** не активируются. Указанные **METHODS** выполняются в порядке их объявления. Если выполнение **METHOD** завершается по незапланированной причине, последующие **METHODS** не выполняются. Если операция **POST\_WRITE\_ACTION** завершается неудачно, приложение EDD игнорирует ошибку.

При попытке записи **DEVICE VARIABLE** на устройство операция **WRITE** может завершиться неудачно (из-за сбоя **PRE\_WRITE\_ACTIONS** или **POST\_WRITE\_ACTIONS** переменной, либо ошибки связи с устройством). Если **MENU** ссылается на несколько **VARIABLES**, и одна или несколько **VARIABLES** успешно записаны на устройство, **POST\_WRITE\_ACTION** меню активируется. Если ни одна **VARIABLE** не была успешно записана, **POST\_WRITE\_ACTION** меню не активируется.

Примеры см. в разделах **D.1.11** и **D.1.12**.

{% code title="Lexical structure" overflow="wrap" %}
```c
POST_WRITE_ACTIONS {actions-specifier} action-specifier := [reference [, reference]*]? [DEFINITION {compound-statement}]?
```
{% endcode %}

**Атрибуты POST\_WRITE\_ACTIONS** определены в **Таблице 82**.

## 11.1.9 PRE\_EDIT\_ACTIONS

**Атрибут PRE\_EDIT\_ACTIONS** определяет **METHODS**, которые должны выполняться после любых **INIT\_ACTIONS**, **PRE\_READ\_ACTIONS** или **POST\_READ\_ACTIONS** во время сеанса редактирования.

**Условия выполнения:**

* **PRE\_EDIT\_ACTIONS** не активируются в сеансе только для чтения
* Если **MENU** находится в прерванном состоянии (сбой **INIT\_ACTIONS** или **PRE\_READ\_ACTIONS**), **PRE\_EDIT\_ACTIONS** не запускаются

**Правила обработки:**

1. Указанные **METHODS** выполняются последовательно в порядке объявления
2. При аварийном завершении **METHOD**:
   * Последующие **METHODS** не выполняются
   * Приложение EDD уведомляет пользователя об ошибке
   * Элементы становятся недоступными для редактирования

**Примеры:** См. разделы **D.1.7** и **D.1.8**.

{% code title="Lexical structure" overflow="wrap" %}
```c
PRE_EDIT_ACTIONS {actions-specifier} action-specifier := [reference [, reference]*]? [DEFINITION {compound-statement}]?
```
{% endcode %}

## 11.1.10 PRE\_READ\_ACTIONS

**PRE\_READ\_ACTIONS** активируются только при **ONLINE**-доступе. Это включает случаи, когда атрибут **ACCESS** меню имеет значение **ONLINE**, даже если сессия в целом работает в **OFFLINE**-режиме. Атрибут **PRE\_READ\_ACTIONS** определяет **METHODS**, которые должны выполняться сразу после активации и завершения **INIT\_ACTIONS**.

Если **MENU** находится в прерванном состоянии (сбой **INIT\_ACTIONS**), **PRE\_READ\_ACTIONS** не активируются. Указанные **METHODS** выполняются в порядке их объявления. Если выполнение **METHOD** завершается по незапланированной причине:

* Последующие **METHODS** не выполняются
* Пользователю отображается уведомление об ошибке
* Содержимое **MENU** не отображается (приложение EDD рендерит **MENU** как пустое, например, **GROUP** или **PAGE** отображают только свой **LABEL**)

После завершения **PRE\_READ\_ACTIONS** меню приложение EDD может приступить к стандартному рендерингу.

**Примеры:** См. разделы **D.1.4**.

{% code title="Lexical structure" overflow="wrap" %}
```c

```
{% endcode %}

## 11.1.11 PRE\_WRITE\_ACTIONS

Указанные **METHODS** выполняются в порядке их объявления. Если выполнение **METHOD** завершается по незапланированной причине, последующие **METHODS** не выполняются.

**Примеры:** см. в разделе **D.1.10**.

PRE_WRITE_ACTIONS {actions-specifier} action-specifier := [reference [, reference]*]? [DEFINITION {compound-statement}]?

{% endcode %}

Атрибуты **PRE\_WRITE\_ACTIONS** определены в **Таблице 82**.

## 11.1.12 STYLE

**Атрибут STYLE** определяет способ отображения **MENU**.

Когда атрибут **STYLE** имеет значение **DIALOG**, **WINDOW**, **PAGE** или **GROUP**, квалификатор **DISPLAY\_VALUE** (см. Таблицу 81) применяется автоматически к каждому элементу **MENU**.

Если один или несколько **MENU** активны и активируется **DIALOG MENU**, он получает приоритет и должен быть закрыт перед использованием любого другого **MENU**.

{% code title="Lexical structure" %}
```c
STYLE [DIALOG | WINDOW | PAGE | GROUP | MENU | TABLE];
```
{% endcode %}
