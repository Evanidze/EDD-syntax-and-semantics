# 11.5 CHART (диаграмма)

## 11.5.1 General structure

**CHART** описывает график, используемый для отображения данных от устройства в приложении EDD по мере их изменения во времени. **CHART** предназначен для отображения непрерывных значений данных с устройства, в отличие от **GRAPH**, который используется для статического набора данных.

В приложении EDD для отображения на **CHART** указывается один или несколько **SOURCE** (источников). Данные с устройства могут быть скорректированы перед отображением с помощью **INIT\_ACTIONS** и **REFRESH\_ACTIONS**, применяемых к элементам **SOURCE** в составе **CHART**.

Цвет фона графика **CHART** определяется приложением EDD. Для обеспечения единообразия рекомендуется использовать белый фон. Также рекомендуется, чтобы приложение EDD поддерживало одновременное отображение как минимум шести кривых.

Язык EDD может предоставлять подписи и справочную информацию для **CHART**, его кривых и осей. Для формирования легенд и справки о кривых приложение EDD должно поддерживать правила, определённые в разделе **11.5.6**.

Приложения EDL, не поддерживающие графическое отображение **CHART**, должны показывать связанные переменные в стандартном числовом формате. Например, данные могут быть представлены в табличной форме. Выбор формата остаётся за разработчиком приложения EDD.

{% code title="Lexical Structure" %}
```c
CHART identifier {
    LABEL string-value;
    HELP string-value;
    CYCLE TIME integer-expression | integer-expression<cond>;
    HEIGHT height-width-specifier;
    LENGTH integer-expression | integer-expression<cond>;
    MEMBERS { members-specifier }
    TYPE chart-type-specifier;
    VALIDITY boolean-specifier;
    VISIBILITY boolean-specifier;
    WIDTH height-width-specifier;
}
```
{% endcode %}

## 11.5.2 CYCLE\_TYME

**Атрибут CYCLE\_TIME** определяет временной интервал (в миллисекундах), через который приложение EDD должно считывать значения источника (и выполнять связанные **REFRESH\_ACTIONS**) из устройства. По умолчанию, если атрибут **CYCLE\_TIME** не задан, цикл обновления для **CHART** составляет **1 000 мс**.

**Примечание:** Из-за особенностей работы приложения EDD (например, задержек при мультиплексированном вводе-выводе) фактический цикл обновления может отличаться от заданного, включая вариации скорости обновления, задержки и джиттер. Если приложение не успевает считывать данные с заданной частотой, оно делает это настолько быстро, насколько возможно.

Хотя **CYCLE\_TIME** может ссылаться на **VARIABLE**, приложение EDD должно фиксировать его значение на всё время отображения **CHART**. **CYCLE\_TIME** определяется сразу после выполнения **INIT\_ACTIONS**, но до отображения графика.

Значение **CYCLE\_TIME** остаётся неизменным, пока **CHART** открыт. Если график закрыть и снова открыть, он может получить новый **CYCLE\_TIME**.

**Поддерживаемые профили связи:** HART

**Минимальное значение CYCLE\_TIME** — **1 000 мс**. Если задано меньшее значение, оно автоматически увеличивается до **1 000 мс**.

## 11.5.3 LENGTH

**Атрибут LENGTH** определяет временной интервал (в миллисекундах), отображаемый на графике **CHART**. Количество отображаемых выборок можно рассчитать, разделив значение **LENGTH** на **CYCLE\_TIME**.

По умолчанию, если атрибут **LENGTH** не задан, временной диапазон графика составляет **600 000 мс** (10 минут).

Хотя **LENGTH** может ссылаться на **VARIABLE**, приложение EDD фиксирует его значение на всё время отображения **CHART**. **LENGTH** вычисляется и сохраняется сразу после выполнения **INIT\_ACTIONS**, но до отображения графика.

Если график закрыть и снова открыть, он может получить новое значение **LENGTH**.

## 11.5.4 TYPE

Атрибут **TYPE** определяет тип графика **CHART**, который должно отображать приложение EDD. Поддерживаются три (3) типа индикаторов и три (3) типа трендовых графиков. Типы индикаторов: **GAUGE**, **HORIZONTAL\_BAR** и **VERTICAL\_BAR** (показаны на Рисунке 52). Трендовые графики: **SCOPE**, **STRIP** и **SWEEP** (показаны на Рисунке 51). По умолчанию, если атрибут **TYPE** не указан, используется тип **STRIP**.

Для графиков типа индикатора все **SOURCE** с одинаковой осью **Y\_AXIS** группируются и отображаются на одном индикаторе. Индикатор подписывается меткой (**LABEL**) из **Y\_AXIS**. Каждая указанная ось **Y\_AXIS** в **CHART** создает новый индикатор, и все индикаторы располагаются последовательно. Цвет отображения переменной определяется по правилам из раздела **14.10**. Индикаторы группируются с использованием метки **CHART** для удобства пользователя.

## 11.5.6 Правила оформления легенды/справки для CHART

### 11.5.6.1 Индикаторы и тренды (Y\_AXIS не определен) - одна VARIABLE на SOURCE

1. Приложение EDD должно отображать метку/справку в легенде, используя описание/справку элемента CHART.&#x20;
2. Если описание/справка элемента CHART не определено или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием метки/справки ссылки на источник (SOURCE).&#x20;
3. Если метка/справка SOURCE не определена или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием описания/справки элемента SOURCE.&#x20;
4. Если описание/справка элемента SOURCE не определено или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием метки/справки ссылки на VARIABLE (для метки и справки ссылки на переменную см. также "Конкатенация меток для косвенных ссылок на переменные" и "Конкатенация справки" в FCG TS61804-4).

### **11.5.6.2 Тренд (Trend)  (Y\_AXIS не определен) – Две или более VARIABLES на один SOURCE**

1. Приложение EDD должно отображать метку/справку в легенде для трендового графика (strip, sweep и scope), используя описание/справку элемента SOURCE.&#x20;
2. Если описание/справка элемента SOURCE не определено или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием метки/справки ссылки на VARIABLE (для метки и справки ссылки на переменную см. также "Конкатенация меток для косвенных ссылок на переменные" и "Конкатенация справки" в FCG TS61804-4)

### **11.5.6.3 Индикаторы (Meter) (Y\_AXIS не определен) – Две или более VARIABLES на один SOURCE**

1. a) Приложение EDD должно отображать легенду (для нескольких источников) индикаторного графика (HORIZONTAL\_BAR, VERTICAL\_BAR и GAUGE), используя описание/справку элемента CHART.
2. Если описание/справка элемента CHART не определено или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием метки/справки ссылки на источник (SOURCE).
3. Дополнительно график должен отображать отдельную метку/справку "легенды столбцов" для каждого столбца, используя описание/справку элемента SOURCE.
4. Если описание/справка элемента SOURCE не определено или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием метки/справки ссылки на VARIABLE (для метки и справки ссылки на переменную см. также "Конкатенация меток для косвенных ссылок на переменные" и "Конкатенация справки" в FCG TS61804-4).

### **11.5.6.4 Трендовый (Trend) график (Y\_AXIS определен) - Одна VARIABLE на SOURCE и два (или более) общих SOURCE**

1. Применяются те же правила обозначений, что и в пункте 11.5.6.1.
2. Дополнительно должна отображаться легенда оси с использованием метки AXIS.

### **11.5.6.5 Индикаторы (Meter) (Y\_AXIS определен) – Одна VARIABLE на SOURCE и два (или более) общих SOURCE**

1. Приложение EDD должно отображать каждый источник с одинаковой осью Y, сгруппированные вместе, используя единый индикатор. Для этой общей оси приложение EDD должно отображать каждый SOURCE либо как отдельную горизонтальную/вертикальную шкалу, либо как стрелочный индикатор с использованием круглого или полукруглого циферблата.
2. Приложение EDD должно отображать легенду каждого индикатора (т.е. для нескольких источников) индикаторного графика (HORIZONTAL\_BAR, VERTICAL\_BAR и GAUGE) с использованием метки AXIS.
3. Дополнительно приложение EDD должно отображать отдельную метку/справку "легенды шкалы/стрелки" для каждой шкалы, используя описание/справку элемента CHART.
4. Если описание/справка элемента CHART не определено или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием метки/справки ссылки на источник (SOURCE).
5. Если метка/справка SOURCE не определена или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием описания/справки элемента SOURCE.
6. Если описание/справка элемента SOURCE не определено или является пустой строкой (""), то метка/справка в легенде должна отображаться с использованием метки/справки ссылки на VARIABLE (для метки и справки ссылки на переменную см. также "Конкатенация меток для косвенных ссылок на переменные" и "Конкатенация справки" в FCG TS61804-4).
